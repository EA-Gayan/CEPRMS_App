  PHASE 1 — AUTHENTICATION  [ ✔ COMPLETE ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Page:  /login

  Frontend
  ────────
  • Toggle tabs: "Sign In" / "Create Account"
  • Role selector on register: Patient | Doctor
  • Patient-specific field: National Health ID
  • Doctor-specific field: Specialization
  • Password show/hide toggle

  Backend API Endpoints
  ─────────────────────
  POST  /api/auth/register   →  Create patient or doctor account
  POST  /api/auth/login      →  Validate credentials, set httpOnly JWT cookie
  POST  /api/auth/logout     →  Clear JWT cookie
  GET   /api/auth/me         →  Return current user from JWT

  Security Controls
  ─────────────────
  [1] Rate limiting on /login: max 20 requests per hour (blocks brute-force)
  [2] Rate limiting on /register: max 10 requests per hour
  [3] Passwords hashed with bcrypt before storage (never stored in plain text)
  [4] JWT stored in httpOnly + SameSite=Lax cookie (mitigates XSS attacks)
  [5] JWT payload carries role claim — verified server-side on every request
  [6] All login/register events written to MongoDB audit_logs collection

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Page A: Patient Dashboard  (/patient/dashboard)                        │
  └─────────────────────────────────────────────────────────────────────────┘

  Frontend
  ────────
  • Summary profile card (name, NHI, account status)
  • List of past medical visit records
  • Current medications panel

  Backend API
  ───────────
  GET  /api/patient/profile      →  Return profile from JWT identity
  GET  /api/patient/my-records   →  Return own encrypted+decrypted records

  Security Controls
  ─────────────────
  [1] Patient ID is read STRICTLY from the signed JWT — never from URL params
      (Prevents IDOR: Insecure Direct Object Reference attacks)
  [2] Records are stored AES-256-GCM encrypted in MongoDB
      and decrypted only on authorized GET requests

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Page B: Consent Management  (/patient/consent)                         │
  └─────────────────────────────────────────────────────────────────────────┘

  Frontend
  ────────
  • List of doctors currently authorized with [Revoke Access] button
  • "Grant Access" panel: select Doctor ID + set expiry window (e.g. 2h, 8h)

  Backend API
  ───────────
  POST  /api/consent/grant    →  Create time-limited consent record
  GET   /api/consent/active   →  List all active (non-expired) grants
  POST  /api/consent/revoke   →  Mark a consent record as revoked

  Security Controls
  ─────────────────
  [1] Consent records store expiry timestamps — expired grants auto-denied
  [2] Revocation is validated server-side before any DB write
  [3] Every grant/revoke action is written to audit_logs

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Page A: Doctor Dashboard  (/doctor/dashboard)                          │
  └─────────────────────────────────────────────────────────────────────────┘

  Frontend
  ────────
  • Search bar: find patients by Full Name or National Health ID
  • Results show basic metadata only (Name, ID, consent status icon)

  Backend API
  ───────────
  GET  /api/doctor/search-patients?q=<query>  →  Search patients

  Security Controls
  ─────────────────
  [1] Search results NEVER include sensitive medical data
      — only Name, NHI, and a boolean "has_consent" flag
  [2] Only doctors (role=doctor) can access this endpoint
      enforced by @role_required("doctor") decorator

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Page B: Patient Record View  (/doctor/patient/:id)                     │
  └─────────────────────────────────────────────────────────────────────────┘

  Frontend
  ────────
  • Left panel: decrypted diagnosis & treatment history (chronological)
  • Right panel: form to submit new clinical notes / prescriptions

  Backend API
  ───────────
  GET   /api/records/view/<patient_id>  →  Fetch & decrypt patient records
  POST  /api/records/add/<patient_id>   →  Encrypt & store new treatment note

  Security Controls
  ─────────────────
  [1] ABAC Core Filter: @verify_consent decorator checks MongoDB for an
      active, unexpired consent grant between current_doctor_id and patient_id
      → Returns HTTP 403 Forbidden immediately if no valid grant found
  [2] New treatment notes are AES-256-GCM encrypted before DB insert
  [3] Records are decrypted in-memory only for authorized GET requests
  [4] Every view and write is logged to audit_logs with full timestamp

  Frontend
  ────────

  • Columns: Timestamp | Actor | Role | Action | Target

  Backend API
  ───────────
  GET  /api/admin/logs  →  Return paginated audit log entries

  Security Controls
  ─────────────────
  [1] Endpoint locked behind @role_required("admin") — JWT role check
  [2] Logs are READ-ONLY — no modification or deletion endpoints exist
  [3] Sample log entries:
      "Doctor Smith viewed Patient Doe's file on 2026-05-25 at 11:52"
      "Patient Doe revoked Doctor Smith's access on 2026-05-25 at 14:30"
      "New user registered: role=patient on 2026-05-25 at 09:15"

  Collection: users
  ─────────────────
  {
    _id:                ObjectId,
    email:              String  (unique, indexed),
    password_hash:      String  (bcrypt),
    role:               "patient" | "doctor" | "admin",
    full_name:          String,
    national_health_id: String  (patients only, sparse index),
    specialization:     String  (doctors only),
    created_at:         DateTime,
    is_active:          Boolean
  }

  Collection: medical_records
  ───────────────────────────
  {
    _id:               ObjectId,
    patient_id:        ObjectId  (ref: users),
    doctor_id:         ObjectId  (ref: users),
    encrypted_notes:   String    (AES-256-GCM ciphertext),
    record_type:       "diagnosis" | "treatment" | "prescription",
    created_at:        DateTime
  }

  Collection: consent_grants
  ──────────────────────────
  {
    _id:        ObjectId,
    patient_id: ObjectId  (ref: users),
    doctor_id:  ObjectId  (ref: users),
    granted_at: DateTime,
    expires_at: DateTime,
    is_revoked: Boolean
  }

  Collection: audit_logs
  ──────────────────────
  {
    _id:        ObjectId,
    actor_id:   String,
    actor_role: String,
    action:     String,
    target_id:  String,
    timestamp:  DateTime,
    meta:       Object
  }

  SECURITY SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Threat                  Mitigation
  ──────────────────────  ────────────────────────────────────────────────────
  Brute-force login       Rate limiting (Flask-Limiter): 20 req/hour on /login
  XSS cookie theft        JWT in httpOnly + SameSite=Lax cookie
  Password breach         bcrypt hashing (never stored in plaintext)
  IDOR (URL tampering)    Patient ID sourced from JWT, not URL params
  Unauthorized records    @verify_consent ABAC check on every record access
  Data breach (DB leak)   AES-256-GCM encryption on all medical record fields
  Privilege escalation    role claim embedded in JWT + @role_required() guard
  Forensic traceability   Immutable audit_logs collection (read-only API)
